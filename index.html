Built for integration

Ballerina solves the integration problem.

Build connected applications that bring together multiple systems, data, and services, with built-in support for security, concurrency, and reliable, long-running execution.

Built for agents

Building agents is an integration problem.

Agents need to reason, use tools, access enterprise data, and execute real-world actions reliably. That’s integration, and it’s at the heart of Ballerina.

Ballerina for Integration

Build integrations that connect your systems, data, and services.

Integrations call systems you don’t control, over networks that fail. Ballerina handles this in the language with services, clients, typed data, checked errors, and safe concurrency.

Ballerina for AI

Build agents that work with enterprise systems.

Enterprise agents need models, tools, and other agents. Ballerina brings them together with the same language constructs and connectors used to build integrations.

The diagram is a view of the same source, not a separate artifact. Type and client declarations are omitted. Order and Triage are declared types: the compiler checks every use of their fields, and the API and model responses are checked against them at runtime, so a malformed response surfaces as an error.

AI for Ballerina

Generate reliable code with AI.

More integration code is now generated than typed. The model describes the integration, Ballerina handles the plumbing, and you review the result as code and as a diagram.

Why Ballerina

Integration and AI concepts, built into the language.

Cloud native

Services, listeners, clients, and resources are first-class language constructs, not library afterthoughts.

More info →

AI built in

Model providers, agents, MCP clients and services, and retrieval are part of the standard library, with the same types and error handling as the rest of your code.

More info →

Graphical

Code and diagrams are two views of one source, so editing either updates the other.

More info →

Data oriented

JSON and XML are native types. Query expressions turn one message format into another in a few lines.

More info →

Flexibly typed

Types describe data by its shape. The compiler checks how you use it, and incoming data is validated when it binds to a type.

More info →

Concurrent and durable

Workers without asynchronous functions, plus durable workflows and agents that keep state across crashes and restarts.
