AI-assisted development

AI in your editor. Ballerina in your build.

These tools help you write, map, test, and keep Ballerina integrations in line with their requirements. They run while you develop, not inside the deployed integration. Review generated code and suggestions as you would any other change. To add models and agents to the integration itself, see Ballerina for AI.

Describe it. Review it. Ship it.

Copilot in the editor helps you build both AI and non-AI integrations from natural language. Ask it to generate a service, map data between types, answer questions about Ballerina, or draft tests, then review and edit the code it produces like any other code.

Copilot is a WSO2 Integrator capability (platform-specific) available in VS Code. Its slash commands include /ask, /doc, /openapi, /typecreator, and /data-map, and it can generate tests and restore earlier checkpoints. Generated code is a starting point: compile it, test it, and review it before it reaches production.

Requirements in. Code out. Drift caught.

Keep requirements, code, and documentation in sync. Generate an implementation and tests from high-level business requirements, then check later changes for drift between what the requirements say and what the code does.

Requirements-to-code and drift detection are offered through Copilot's /natural-programming command, which the WSO2 Integrator documentation labels experimental (platform-specific). Drift checks use a model at development time, so treat each finding as a suggestion to review, not as proof that the code matches or violates a requirement. Tests generated from requirements give you a repeatable check that does not depend on the model.

Prompts at build time. Plain Ballerina at run time.

Generate code from a prompt while the project compiles. Annotate an external function with @natural:code to have the compiler generate its body, or use a const natural expression to generate typed constant data, such as realistic test fixtures.

Compile-time code generation is an experimental language feature, introduced in Ballerina 2201.13.0 and still available in 2201.14.0 through the ballerina/ai.np compiler extension. Builds need the --experimental flag and a code-generation service configured through the BAL_CODEGEN_URL and BAL_CODEGEN_TOKEN environment variables, which the VS Code command Ballerina: Configure default WSO2 model provider sets up (platform-specific). The model runs during the build, not when the program runs. Review and test the generated code as you would any other code. This is different from runtime natural expressions, which call a model each time the program runs.

import ballerina/http;

public type Product record {|
    string id;
    decimal price;
|};

final Product[] productCatalog = [
    {id: "PROD001", price: 999.99},
    {id: "PROD002", price: 699.99},
    {id: "PROD003", price: 29.99},
    {id: "PROD004", price: 19.99},
    {id: "PROD005", price: 49.99}
];

function filterProductsAbovePrice(Product[] products, decimal priceThreshold) returns Product[] = @natural:code {
    prompt: "Filter products that have a price greater than the given price threshold."
} external;

service / on new http:Listener(8080) {
    resource function get products/filter(decimal minPrice) returns Product[]|http:BadRequest {
        return filterProductsAbovePrice(productCatalog, minPrice);
    }
}
